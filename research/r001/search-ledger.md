## Source and implementation discrepancies

- AdaMuon v3 uses sign preprocessing and removes the v1 bias correction. Both
  are distinct variants; the newest variant must not be replaced by v1.
- Variance-Adaptive Muon v2 has new experiments and an EMNLP repository. Its
  paper uses the recurrence and bias correction recorded in `peer-updates.md`.
  The pinned Suite_A code rescales small gradients upward using `clamp(min=1)`
  in a helper described as clipping. That source behavior needs a named parity
  variant; silently fixing it would change the comparator.
- DeVA v2 explicitly rotates the update back, which v1 Algorithm 2 omitted.
  Pinned code also has first-step skip, Nesterov, bias correction and decay after
  updating the weights. Preserve these differences in Phase 03 parity checks.
- The SPECTRA framework and the unrelated Spectra spike optimizer have distinct
  arXiv IDs, authors, updates and code. Neither replaces the other.
- Dion3 is the NorDion2 code alias at the pin; paper includes optional NorMuon.
  Register normalized and unnormalized selected-row variants, plus full rows.
- Physical Muon is eligible because its paper publishes Euler/probe iterations;
  the smoothed polar-flow paper supplies continuous-time analysis only and is
  context, not an invented discrete baseline.
- OptMuon v2 allows a nonmonotone tracker and changes Option A's accumulated
  energy. The exact v2 rule is retained; no official code was located.
- Some repositories have no root `LICENSE`. Failed retrievals are preserved in
  the manifest. Read-only inspection is recorded; future redistribution needs
  license resolution. This does not remove an eligible comparison from the list.

## Saturation and remaining coverage

Multiple observation/objective queries converge on SAGE, SPECTRA and low-rank
proximal calculus. Forward retrieval added numerical routines; they do not use
the proposed simultaneous difference penalty. The registry freezes the discovered
eligible discrete methods, with explicit source versions and variant IDs. It is
not the set of every optimizer ever written. Unpublished, private, non-English,
patent-equivalent and unindexed implementations remain unresolved. Before Phase
08, refresh the search and create a new protocol revision if eligibility changes.

**Novelty outcome:** apparently distinct specific estimator/objective/constraint
instantiation within this corpus. New primitives are not established: covariance
risk, replica observations, spectral clipping and low-rank proximal solving are
all occupied. Equivalent prior instantiation remains a novelty kill criterion.
